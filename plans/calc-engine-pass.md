# Calc engine pass: build brief

The brief for the sessions that build `plans/calc-dynamic-power.md` → "Engine pass 2026-10-26" (the unit table, the
survey findings and the input contract live there; this file says how to run it). Written 2026-10-26; the user
approved the unit list the same day. Delete this file with the units' plan text when the pass is merged (CLAUDE.md →
plans hold work not done yet).

## Decisions (user, 2026-10-26)
- Scope A-D as in the unit table. Out of scope: anything under `template/` except `template/calc/engine.js`
  (generated by `tools/calc/build.mjs`); no `calc.js`, `calc.css`, row or card UI. The UI spec
  (`origin/worktree-damage-calc-toggles:plans/calc-state-toggles.md`) is read-only here and not built.
- Per-move crit stages: **(a) a `cr` field per move in `data.json`**, written by each hack's extract from its game data
  or source (only moves whose stage is not 0; `6` or more = always a crit, as the 3DS dumps write it). **Fallback (b)**
  per hack where the source can't give a clean per-move stage: a generated `cfg.calc.over.moves[name].critStage` list
  in that hack's `hack.json`, with the reason in its notes.md. Extract and data changes for `cr` are approved; any
  other extract or data change still needs the user first.
- Focus Energy: field keys `atkFocus` / `defFocus`, read by the adapter; the UI build declares them in
  `template/calc/profiles/` (not this pass). Confirmed by the user 2026-10-26 (built that way in U6).
- A guaranteed crit (stage at the generation's always-crit threshold, `willCrit`, Merciless on a poisoned target,
  Laser Focus) is applied whatever `slot.crit` says, and the result says so (`crit.forced`) so the UI can lock C on.

## Roles
- **Orchestrator: Opus medium**, the main chat in `.claude/worktrees/damage-calc` (branch `worktree-damage-calc`).
  Dispatches the Sol units, writes all `tools/calc/` code (U3, U4, U6), the extract `cr` changes, and U7.
- **Sol** (`gpt-6.1-sol`; confirm the ID with `orchestrator_capabilities` first) via `delegate_task`, **shared
  worktree**: the brief gives the absolute worktree path, and the worker works there (no `isolation: "worktree"`: T3
  worktrees start from `main`, which lacks the calc). Sol writes only `plans/` notes and fixture files
  (`hacks/<hack>/calc_states.json`), never `tools/calc/src`, `template/`, extract scripts or `data.json`.
- **Fallback: Haiku medium**, under 100k context, finishes a Sol unit from its last `WIP:` commit (same brief plus the
  WIP commit and the unit's notes so far). A Haiku job that would pass 100k is split per hack.
- One Sol unit runs at a time (they share the worktree and the orchestrator commits there too): dispatch, wait
  (`task_status`, bounded), review the commit, then the next. While a Sol unit runs the orchestrator does not edit the
  files it owns; adapter work in `tools/calc/src` can run alongside.
